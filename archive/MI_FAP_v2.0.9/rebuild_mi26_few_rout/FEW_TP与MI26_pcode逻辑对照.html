0. 结论速览

总判定：核心工艺逻辑（IO 动作序列）五条指令全部对齐，具备互换基础；但互换不是「换名字」—— 有 2 个 P0 级改造点必须先关闭，否则换版本会出生产事故。

判定说明
🔴 P0-1FEW_WELD 实参序相反 TP：FEW_WELD(ProgNo, OpenPos)；MI26 手册/实现：MI26_FEW(3, GunNo, OpenPos, ProgNo)。 直接换调用名不改参数 = ProgNo/位置互换 → 焊错程序号或开口值。
🔴 P0-2DockON 的 DO[3883] 极性分歧（唯一真实信号分歧） TP FEW_DOCK_ON：DO[3883]=OFF；pcode MI26_FEWDOCK CASE(1)：DO+11=ON（字节码 INT 1 实证，且 CASE 不复位）。 TP 侧经现场验证，pcode 侧未经本机验证——须设备/PLC 侧确认正确工况后再定改哪边。
🟡 P1PNIO attach 66 只在 TP 版 TP DOCK_ON 头部 / DOCK_OFF 尾部有 PNIO attach 66；pcode 无对应动作（疑由 MI01 框架/PLC 侧负责）。 互换前确认 PROFINET 设备 66 的挂载在 MI26 路径下不丢。
🟡 P1错误处理哲学不同 TP：WAIT 死等 + 手工恢复路径（LBL[88] PAUSE 重跳 / LBL[99] UALM）；pcode：3s/8s 超时 + DB_PROMPT 重试/跳过 + 超时自动 FEW_REQ_FEEDER。 互换后产线异常处置流程（操作/工艺）跟着变。
🟢 P2时序宽度与动作毛刺 DO[3873] 脉宽 0.5s(TP) vs 1.0s(pcode)；焊启前延时 2.0s vs 0.5s；Init 时 TP 对 DO[3881] 先 OFF0.5s 再 ON、pcode 直接 ON。 同终态，大概率无害，实测确认。
✅DI[35] 跳过语义 / IO 映射 / 主序列 全部一致（DI[35] 由字节码 RET 实证；IO 基址 .vr 实配与 TP 硬编码逐点相等）。

互换改造公式：调用点改名 + FEW_WELD 参数换序 + Dock 参数 1/2（DockON/DockOFF）+ GunNo 显式传 1 + 确认 PNIO 兜底 + 关闭 DO[3883] 分歧。

2. IO 映射对照（完全一致 已验证）

TP 版硬编码枪 1 的信号块；MI26 版通过 AR_I_MI26_*[GunNo] 可配基址。本机 .vr 实配与 TP 硬编码逐点相等：

通道TP 硬编码（枪1）MI26 实配（mi26_few_var.vr）偏移语义（两版共用）

DO / DI 基址38723872（枪2/3=UNINIT） +9=使能(3881)，+11=定位模式(3883)，+12=3884，+13=焊启(3885)，+14=3886，+10=Home(3882)， +3=Release(3875)，+21=Dock(3893)，+23=充钉(3895)，+2=3874，+4=3876；DI+1=就绪(3873)，+5=允许启动(3877)， +9=自动(3881)，+12=目标有效(3884)，+13=焊完(3885)，+10=Homed(3882)，+3=Release(3875)，+21=Docked(3893)，+23=充钉请求(3895)

MI26 的多枪能力（GunNo 1-3）是超集；本测试机只有枪 1 配置。互换即插即用的前提：枪号显式传 1。

6. 互换验收清单（建议顺序）

  1. 关闭 P0-2：设备/PLC 确认 DockON 工况 DO[3883] 应为 ON 还是 OFF——若 OFF 为正确，改 MI26_FEWDOCK CASE(1)（库侧一行）或接受 TP 行为为基准；
  2. 调用点改造：按 §4 公式改写（FEW_WELD 换序是重中之重），建议先改 testfew 类测试程序试跑；
  3. 确认 PNIO attach 66 在 MI26 路径下的兜底（MI01 初始化/PLC 侧）；
  4. 按五指令各做一次空跑/实跑对照（同工况双版本各跑一遍，比对 DI/GO 时序截图或 PLC trace）；
  5. 确认异常流程切换（pcode 的 DB_PROMPT 重试环需要操作工会响应 Retry/Cancel）；
  6. 回归：连续生产观察焊点质量与 ProgNo 命中（重点 FEW_WELD 参数序改造正确性）。
