2. 执行时序

2.1 开机装载时序【实证】

上电 → USER_LOADER (karel 2.0.9)
        ├─ IF UNINIT(BG_PRG) → BG_PRG = 'UserAutoExec'   // 后台任务名可配置
        ├─ IF io_0e[128] = 0                            // 启动门（软开关/模式位）
        │    RUN_TASK(BG_PRG, 0, …, 1, L_STATE)          // 拉起后台任务
        │    IF L_STATE <> 0 → POST_ERR(38100,'User task run failed')
        └─ END
   BG_PRG(UserAutoExec) → 各应用 INIT 例程（见 2.2）

2.2 应用 INIT 时序（四件套入口，SSW 为样例【实证】）

INIT:
  ① IO 基址默认化（UNINIT 逐项: DI/DO 基址、TD 修磨器×2、SW 焊枪、GI/GO 组、FRES 电源…）
  ② 工艺参数默认化（I_ACK_TIME=500  I_VALVEDELAY=2000  I_WELDTIMER=1  I_GUNCOUNT=1…）
  ③ 协议适配 SELECT I_WELDTIMER OF            // 三种焊控接口协议
       CASE(2): DI/DO 位映射表 = {WELD_END=1, MILLING_DEMAND=2, PREWARNING=3,
                REQELECCHG=4, READY=5, SPOT_SELECTION_OK=20 / START=1, ACK=5…}
       CASE(3): 另一套位映射（WELD_END=3, READY=4…）
       ELSE: (空——协议号不匹配时静默无动作 ⚠ 见缺陷 B5)
  ④ B_MON_04 = 1（监控使能）→ RUN_MONITOR('MI04_ssw_mon')  // 拉起后台监控任务
  ⑤ RETURN

2.3 监控循环时序（_mon 主体每轮，SSW_MON【实证】）

每轮（事件 CONDITION 唤醒 + 周期轮询）:
  ① 采集:   GET_REG(36/39, …, I_STATUS) → 换算(round ×1000 / 单位换算)
  ② 广播:   SET_INT_REG(168, …) ; io_13[I_MI01_GO+13/14] ≤ 65535/255 护栏后写出
  ③ 配置护栏: UNINIT(B_MON_04/B_SENDBSNUM/B_PRESSCHK/B_FLOWCHK…) 默认化
  ④ 事件句柄: PURGE CONDITION[1..3] → 绑定 DI 边沿（104=I_MI04_DI+1 焊完、106=I_MI01_DI+48）
            ENABLE CONDITION[1]（仅 I_WELDTIMER=3 协议启用）
  ⑤ 功能块分发（每轮按标志位）:
       B_SENDBSNUM      → MI04_SENDBSNUM(0)      // 焊点编号上送
       B_FLOWCHK ∧ 枪号 ∧ DI=0 → MI04_FLOWOK(I_TIPDRESSNO) // 流量/修磨检查
       无条件            → DRYORWETMODE / SETGUNOPERAT / RECORD / WELDASSIST
                           （干湿模、焊枪操作、数据记录、焊接辅助——BOSCH 焊控交互）
  ⑥ 等待下一事件/节拍（CONDITION 或轮询）

2.4 联锁握手时序（跨设备/产线）

联锁时序形态【实证】
产线 PLC（MI19_cli）WAIT_SIGNAL(6 参通用握手) + MI19_IOINTER； TOXSTART → 加压/铆接 → TOXEND；SERVO_TOXSTART → SERVO_LOAD → SERVO_TOXEND（伺服压机时序）； UI 等待文案 "Wait Singal ON/OFF"（厂商拼写）
涂胶 SCA（MI08_dsp）TCP_Master ⇄ TCP_Slave 双向（德语串 "Vom Roboter auf TCP Controller"）： 选程序号（Prog Num TCPCtrl）→ 下发深度/时间参数（TCP Depth/Dim）→ purge（Purge_SCA/Purge_DMTS/FILL/Start） → ACK/超时（TCP Time Out）
焊控 BOSCH（MI04_ssw）DI: WELD_END/PREWARNING/REQELECCHG/READY； DO: START/ACKNOWLEDGE/WITH_CURRENT/SPOT_NUM 位段（bit0 起的编码位）；ACK 超时 I_ACK_TIME=500ms； 阀延时 I_VALVEDELAY=2000ms；TipChg: "Wait for ACK TipChg"
安全Deadman switch required（手动/示教使能）；CHECKHOMEPOS/HOLDMOTION（运动安全）； AUTODISABLEWATER（停焊断水）

3. 代码执行到底是什么作用（一句话定位）

这套代码是焊装工艺站的"软 PLC + 设备网关"：把 PLC 的产线信号（握手/联锁）翻译成 工位设备动作（焊控/铆机/胶机/激光/拧紧枪），把工艺结果（焊点号/压力/扭矩/胶量）记录、换算、 回送给 PLC 与上位机，并在示教屏上提供人机界面与异常恢复通道。机器人运动本身在 49 个 .tp 里， KAREL 层负责的是编排、联锁、数据与安全——不是轨迹。

4. 未发现的 bug / 风险（按严重度）

B1 · 寄存器操作大面积不检查状态（高） GET_REG/SET_INT_REG 调用后未校验 I_STATUS 的场景遍布（MI04_SSW_ROUT 13 处、VS_APPCOR 12 处…【实证计数】）。 寄存器通信失败时数据静默错误——焊接数据广播可能发陈值。
B2 · MI08 TCP 协议模块 = 缺陷密集区（高） TCP_MSG 27 错 / TCP_MEA 22 错 / TCP_COMM 11 错（G1 反编译编译错）——报文解析/主从维度交换逻辑 复杂度最高，且带德语原文协议分支。生产环境该区改动风险最高，建议专项审计。
B3 · 跨任务标志无原子保护（中） B_MON_xx/B_SENDBSNUM 等标志在 GUI、MON、ACTION 多任务间读写（RUN_TASK/RUN_MONITOR 多任务模型【实证】）， KAREL 无锁机制——存在标志更新撕裂/丢失唤醒的竞态窗口。
B4 · 事件句柄管理脆弱（中） PURGE CONDITION×140 / ENABLE CONDITION×76 手工配对；反编译可见 stmt 残留（条件句柄边界的语句碎片）。 句柄泄漏或错配会导致监控体丢事件。
B5 · 协议分支 ELSE 为空（中） INIT 的 SELECT I_WELDTIMER OF … ELSE:（空）——焊控协议号不匹配时静默不配置位映射， 后续全部按错误位操作，无报警【实证】。
B6 · UI 文案拼写 "Wait Singal"（低，3 文件） Signal 拼成 Singal（MI19_cli 等【实证】）——显示层 bug，不影响逻辑。
B7 · 人因旁路 "Press OK to force complete"（低） 铆接异常可强制完成（MI14_spr【实证】）——质量追溯风险点，建议旁路留痕审计。

6.3 更新日志反推的 bug 史（2.0.9 修复项 = 历史缺陷清单）

数值溢出类：Coherix 3D TCP 数值小数处理不当 → GO 输出值溢出（2.0.9 修）—— 与本页 B1（寄存器换算不检查）同根源，round(×1000) 类换算在 65535/255 护栏前存在溢出窗口【代码护栏实证】。
时序类：DO ACKNOWLEDGE ERROR/RETRIGGER PUMP/HEAT 脉冲 200ms→1000ms（2.0.9 修）—— 脉冲过短 PLC 丢沿；Run Mode ON 后加 1000ms 延迟再发 GO 型号——设备响应时序补偿。
通信类：Stabli 换枪盘 ChangeTool 读信号状态失败（2.0.9 修）；下挂站掉网 PRIO 报警 （2.0.9 新增 MI01_ERROR 监控 + 自动收 Logbook/DIAG-005）——B3 竞态类风险的官方缓解。
逻辑类：Glue_End 逻辑更改、Walther 5s 自动锁紧从 condition 移入后台—— 印证 B4（CONDITION 句柄管理脆弱）判断。
